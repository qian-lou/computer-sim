# 看见计算机如何工作

一台可以单步拆开的 8 位教学计算机。你写下几行汇编，把它装进 256 字节内存，然后一拍一拍地看指令怎样被取出、译码、执行。界面是简体中文，给第一次接触 CPU 的人用。

打开页面先看到一台打开侧板的电脑：主板有走线、过孔和丝印，内存条有金手指，散热器有鳍片和热管。点击 CPU，飞进带金属互连的芯片；再进 ALU 的 8 位加法器、一位全加器的逻辑门，最后是 CMOS 与非门的剖面。每一层都有中文说明。微步时，发光粒子沿总线移动，寄存器和进位用的是仿真器里的真实数值。按「平面」回到原来的示意图。

## 本地运行

需要 Node.js 22。

```bash
npm install
npm test
npm run dev
```

浏览器打开 [http://localhost:5173/computer-sim/](http://localhost:5173/computer-sim/)。开发服务器和正式构建都使用 `/computer-sim/` 作为站点根路径，和 GitHub Pages 项目站点一致。

```bash
npm run build
npm run preview
```

构建结果在 `dist/`。`npm test` 用 Vitest 检查处理器和汇编器，不需要浏览器。

## 页面上怎么用

1. 选一个示例，或自己改左边的汇编。
2. 按「汇编并装入」。机器码写进内存，程序计数器指到第一条指令。
3. 「微步」只走一拍（取指、译码或执行里的一个小动作）。
4. 「单条指令」把当前这条指令走完。
5. 「运行」按速度滑块连续微步，「暂停」停在当前这一拍，「复位」回到入口并清空寄存器和输出。内存恢复成刚装入的样子。
6. 打开页面就是整台电脑，占满窗口。底部是运行按钮，左下角是这一拍的说明，顶部是层级面包屑。点机箱里的键盘，或按「程序」，才打开汇编编辑器。「指令」打开指令表，「平面」在旁边铺开原来的示意图。手机上这些面板从底部升起。

四个示例：

| 示例 | 在做什么 | 输出 |
| --- | --- | --- |
| 两数相加 | `12 + 30` | 42 |
| 倒计时 | 从 5 减到 1，每次输出 | 5、4、3、2、1 |
| 累加 1 到 10 | 和与计数器放在内存里 | 55 |
| 加法做乘法 | 把 6 连加 7 次 | 42 |

## 机器里有什么

所有的数都是无符号 8 位，范围 0–255。加减只保留低 8 位。

| 名字 | 作用 |
| --- | --- |
| PC | 程序计数器。下一条要读的字节在哪。 |
| IR | 指令寄存器。刚取到的操作码。 |
| ACC | 累加器。运算的主寄存器，结果通常留在这里。 |
| B | 第二个操作数。加法、减法、比较和按位运算用它。 |
| MAR | 内存地址寄存器。当前访问的地址。 |
| MDR | 内存数据寄存器。刚读到、或正要写入的字节。 |
| OUT | 输出寄存器。`OUT` 把 ACC 送到这里。 |
| Z | 零标志。结果是 0 时亮。 |
| N | 负标志。结果的最高位是 1 时亮。把这个字节当成有符号数时，它表示负数。 |
| C | 进位/借位。加法超过 255，或减法不够减时亮。 |

地址总线把“去哪一格”告诉内存，数据总线运送读出或写入的字节。控制单元决定这一拍做哪件事。算术逻辑单元负责加、减、比较和按位运算。内存是 16×16 共 256 个格子。

一条指令的微步固定分成三段：

1. **取指**：PC → 地址总线 → 内存，读出的字节经数据总线进入 MDR，再进入 IR，然后 PC 加 1。
2. **译码**：控制单元对照指令表，认出 IR 里的操作码。
3. **执行**：如果指令后面还跟着一个数或地址，就再读一个字节；然后做运算、访问内存、跳转或输出。

地址加到 255 后再加 1，会绕回 0。

## 指令集

操作数是 0–255 的数，或一个标号（标号代表它的地址）。`A` 也可以写成 `ACC`。

| 操作码 | 写法 | 做什么 | 标志 |
| --- | --- | --- | --- |
| `00` | `NOP` | 什么也不做 | 不变 |
| `01` | `LOAD A, 地址` | 从内存把一个字节装进 ACC | 按装入值更新 Z、N，C 不变 |
| `02` | `LOADI A, 立即数` | 把指令后面的数直接放进 ACC | 同上 |
| `03` | `STORE 地址` | 把 ACC 写入内存 | 不变 |
| `04` | `LOAD B, 地址` | 从内存装进 B | 按装入值更新 Z、N，C 不变 |
| `05` | `LOADI B, 立即数` | 把立即数放进 B | 同上 |
| `10` | `ADD` | ACC = ACC + B | Z、N、C；C 表示超过 255 |
| `11` | `SUB` | ACC = ACC − B | Z、N、C；C 表示借位 |
| `12` | `ADDI 立即数` | ACC = ACC + 立即数 | 同 ADD |
| `13` | `SUBI 立即数` | ACC = ACC − 立即数 | 同 SUB |
| `14` | `AND` | ACC = ACC 与 B | Z、N，C 不变 |
| `15` | `OR` | ACC = ACC 或 B | 同上 |
| `16` | `XOR` | ACC = ACC 异或 B | 同上 |
| `17` | `NOT` | ACC 的 8 位全部取反 | 同上 |
| `18` | `CMP` | 计算 ACC − B，只改标志 | 同 SUB，但 ACC 不变 |
| `20` | `JMP 地址` | 无条件跳转 | 不变 |
| `21` | `JZ 地址` | Z 亮着才跳 | 不变 |
| `22` | `JNZ 地址` | Z 灭着才跳 | 不变 |
| `23` | `JC 地址` | C 亮着才跳 | 不变 |
| `30` | `OUT` | 把 ACC 复制到输出寄存器 | 不变 |
| `FF` | `HALT` | 停机 | 不变 |

不认识的操作码也会停机，避免把空数据当成指令一直跑。程序应当以 `HALT` 结束。

## 汇编语法

```asm
; 分号或 // 后面是注释
.org 0x10          ; 下一条字节从地址 16 开始写
start:  LOADI A, 1 ; 标号独占一行，或跟在指令前面
        ADD
        OUT
        HALT
value:  .byte 42   ; 也可以写成 DB 1, 2, 0x03
```

- 指令和寄存器不区分大小写。标号区分大小写。
- 数可以是十进制 `12`、十六进制 `0x0C`、二进制 `0b1100`。不要写负数。
- 标号以字母或下划线开头。跳转和地址操作数都可以用标号，包括还没定义的标号。
- `.org` 只改变后面字节的存放位置。执行从**第一条指令**开始，而不是从前面的数据开始。
- 同一个地址不能写两次。程序不能超过 256 字节。

## 测试

`src/cpu/cpu.test.ts` 检查每条指令的结果和标志、取指—译码—执行的微步顺序、跳转、停机、复位，以及四个示例的输出。

`src/cpu/assembler.test.ts` 检查机器码、标号、`.org`、进位错误和错误行号。

## 部署到 GitHub Pages

`.github/workflows/pages.yml` 在推送到 `main` 时运行测试、构建，并把 `dist/` 部署到 GitHub Pages。仓库设置里把 Pages 的来源选成 **GitHub Actions**。

站点地址形如 `https://<用户名>.github.io/computer-sim/`。Vite 的 `base` 已设为 `/computer-sim/`，资源路径会带上这个前缀。
